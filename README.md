# Needle 2 Playground

A sandbox for kicking the tyres on **Needle 2**, the 45M-parameter
on-device foundation model from Cactus Compute that lives in a single
~14 MB binary.

> Needle 2 is a *Simple Attention Network* baked into a self-contained
> ARM64 / x86-64 / ARMv7 / RISC-V / WASM engine. No runtime, no network,
> no downloads; ~28 MB peak session RAM, 300-1500 tok/s decode on
> mobile-class hardware.

This repo does three things:

1. Stages the **macOS ARM64** engine (CLI binary + dylib) so we can
   drive Needle from anywhere on the box.
2. Ships a **JSONL scenario corpus** under `scenarios/` covering
   tool calling, extraction, off-topic refusal, conversational loops,
   i18n / unicode, multi-tool dispatch, and stress (large catalogue).
3. Provides a unified **eval harness** in `eval/needle_eval/` that
   loads the corpus, dispatches scenarios through the CLI or the
   Python API, scores each row, and writes Markdown + JSON reports.

## Quick start

```bash
# 1. create a venv and install cactus-needle
python3 -m venv .venv
source .venv/bin/activate
pip install cactus-needle==2.0.2 huggingface_hub httpx tqdm pydantic pytest

# 2. drop the macOS ARM64 dylib next to the package so it loads offline
cp bin/macos-arm64/lib/libneedle.dylib .venv/lib/python*/site-packages/needle/

# 3. smoke-test the CLI
./bin/macos-arm64/needle --tools fixtures/tools/lights.json \
    --prompt "dim the living room to 30" --max 128

# 4. run the full eval suite
python -m eval.needle_eval --runner cli --markdown reports/cli.md
python -m eval.needle_eval --runner python --markdown reports/python.md
```

After step 4 you'll have:

| file | meaning |
| --- | --- |
| `reports/cli.md` | per-category pass / fail table + failure list, CLI runner |
| `reports/cli.json` | machine-readable copy of the same run |
| `reports/python.md` / `python.json` | same, via the `cactus-needle` Python module |

## Scenario corpus

Each `scenarios/<category>.jsonl` row is declarative:

```jsonc
{
  "id": "tc01-dim-living-room",
  "category": "tool_calling",
  "severity": "smoke",
  "tags": ["lights"],
  "tools": [ { /* JSON schema for one tool */ } ],
  "system": null,
  "prompt": "dim the living room to 30",
  "expect": {
    "kind": "call",                       // call | empty | respond | any
    "name": "set_lights",
    "args": {"room": "living room", "brightness": 30, "on": true},
    "min_confidence": 0.5,
    "max_peak_ram_mb": 64.0
  }
}
```

Categories shipped today:

| category        | what it stresses |
| --------------- | --- |
| `tool_calling`  | canonical call, multi-tool, negation, enum, i18n, numeric edges |
| `extraction`    | one declared schema = one tool, used as a parser |
| `off_topic`     | refusal / empty-call contract |
| `conversational`| follow-up turns, reset semantics |
| `system_facts`  | `system:` turn with `date:`, `locale:`, `assistant:` facts |
| `edge_cases`    | empty / long / unicode / special chars / multi-intent / 21.5°C |
| `stress`        | 6-tool catalogue so the retrieval head engages |
| `qualitative`   | synonyms, implicit subjects, polite phrasing |

Add your own rows: edit the existing JSONL or create a new file. The
loader is alphabetically ordered and de-duplicates by id, so adding
fresh `<id>`s is enough — no manifest edits required.

## Eval framework

`eval/needle_eval/` is intentionally small:

* `models.py` — `Scenario`, `Expect`, `Result` dataclasses; `load_jsonl`,
  `load_corpus`, `category_counts`.
* `scoring.py` — pure functions: `score(scenario, output)`, `aggregate(results)`.
  No I/O, easy to unit-test (`tests/test_eval_schema.py`).
* `runners.py` — pluggable invokers: `CLIRunner(bin_path)`,
  `PythonRunner()` for `cactus-needle`. Add your own runner by
  implementing `__call__(scenario, *, max_new_tokens)`.
* `cli.py` + `__main__.py` — `python -m needle_eval`.

```bash
# filter to one category
python -m eval.needle_eval --runner cli --category extraction --quiet

# raw JSON for downstream tooling
python -m eval.needle_eval --runner python \
    --json reports/python.json --markdown reports/python.md --quiet
```

### Scoring rules

For every scenario the harness produces a `Result`:

* **`passed`** is true iff the engine output satisfies the expectation
  shape (`kind`, `name`, subset `args`), the reported `confidence` is
  at or above `min_confidence`, and the engine's `peak_ram_mb` is
  within `max_peak_ram_mb`.
* `score` is a 0..1 confidence-weighted pass score; the summary
  averages it across rows.
* `aggregate` produces `{total, passed, score, by_category: {...}}`
  with a per-category failure list.

The `expect.followup` block is replayed as a second `complete()` after
the first, exercising multi-turn behaviour without forcing the harness
to know about session state.
